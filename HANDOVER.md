# Handover: Moheet's portfolio

For a fresh session that will add a CV and more projects. Read this, then the README.
Everything here was true on 5 October 2026.

## What this is

A single static page at **https://moheetsubudhi.com/**, generated by
`build.py`. No framework, no packages, Python 3 only. The look is a cream notebook-paper poster:
a big centred heading, search under it, icon tiles scattered around it that can be dragged, and a
contact bar (LinkedIn, email, WhatsApp, accent colours) along the bottom. Clicking a tile opens
either a folder (the same poster again, retitled) or a page.

Repo: https://github.com/moheetsubudhi-isb/moheet-portfolio. It holds `build.py`, `art-light.json`,
`icons.json`, `giveaways/01`-`05` and the generated `index.html`. A clean clone rebuilds the page
byte for byte.

## Setup in two minutes

```bash
git clone https://github.com/moheetsubudhi-isb/moheet-portfolio && cd moheet-portfolio
python3 build.py                 # reads ./giveaways, rewrites ./index.html
python3 -m http.server 8911      # then open http://127.0.0.1:8911/
```


## The tree, and how to add things

`views()` in `build.py` builds a list of nodes. Every node is
`{slug, label, icon, title, lede}` plus either `body` (a page) or `children` (a folder).
A node with children renders as its own poster. A path is the slugs joined, like
`projects/ownr`. Tiles, routes, breadcrumbs and search all come from that one list.

Root today: **How to Build with AI** (a folder of nine things, including the skills kit) · **Business Analytics Skills**
(one page) · **My projects** (folder). The root list is near the bottom of `views()`:

```python
root = [
    dict(slug="build", label="How to Build with AI", ..., children=[by[k] for k in ORDER]),
    by["skills"],
    by["projects"],
]
```

### Add a project

Append one `dict` to the `children` of the `projects` node. That is the whole change:

```python
dict(slug="my-thing", label="My Thing", icon="spark",
     title="My Thing",
     lede="One short line.",
     body="""
<p>What it is and why it exists, in plain sentences.</p>
<p><a class="btn primary" href="https://example.com" target="_blank" rel="noopener">Visit it</a></p>"""),
```

`icon` must be a key in `icons.json`. Available: analytics, articles, back, copy, cv, download,
generator, linkedin, local, lock, loop, mail, memory, parts, projects, search, site, skills,
slides, soul, spark, story, tools, whatsapp. For a new one, fetch a Phosphor duotone SVG:
`https://unpkg.com/@phosphor-icons/core@2.1.1/assets/duotone/<name>-duotone.svg` and add it to
`icons.json` under a short key. `cv`, `story`, `articles` and `download` are already there.

Add search keywords for the new node in the `KEYWORDS` dict if the prose does not already contain
the words people will type.

A folder inside a folder works the same way: give a node `children=[...]` instead of `body`. Keep
a project as a **folder with children only if it has real sub-pages**. Until then it is a page.

### Add the CV

Put it as a new node. Decide with him whether it sits at the root beside the other three or
inside a folder. Root is the likelier answer: add a `dict(slug="cv", ...)` to `v` and then add
`by["cv"]` to the `root` list. The `cv` icon already exists.

Suggested shape, in the page's own vocabulary:
- a primary download button first: `<a class="btn primary" href="moheet-subudhi-cv.pdf" download>Download the CV</a>`
- then plain sections: a short opening paragraph, then rows in a `<table>` for roles
  (role, where, dates), then skills as a `<ul>` or `<table>`.
- the old-school feel comes from restraint: a table, mono small caps for headings, no cards.

The PDF and any photo are committed to the repo root (or a `cv/` folder) and linked by relative
path. There is **no image styling yet**, so add a small CSS rule next to `.panel` in the `CSS`
string if a photo is wanted, and keep it inside the cream palette.

Nothing in the page should be a stub. If a section has no content yet, leave the section out.

### Classes you can use inside a `body`

`.panel` with `.panel-head`, `table`, `ul`, `code`, `.rule` (a big pull line), `.formula`,
`.btn` and `.btn.primary`, `.split` (two columns), `details` blocks, `.fig` for diagrams. Bodies
are written in a Python triple-quoted string. **If a body is inside an f-string, every `{` and `}`
must be doubled.** Most are plain strings, so check the neighbouring nodes.

## Rules the page keeps (do not break these)

These came from repeated corrections. Treat them as requirements.

- **One poster at every level.** Same heading, search, scatter, drag and top bar whether a folder
  holds one tile or ten. Never branch on how many items there are. The scatter has no minimum.
- **One tile size.** Tiles do not scale with how few there are.
- **Headings are four or five words, centred.** The subline is one short line in mono.
- **One top bar** on folders and pages: a back pill that names the parent, then a trail showing
  only where you are. The pill already names the parent, so the trail never repeats it.
- **Copy is very short and a little human**, in the tone of "Steal anything." and "Not here.
  Ask me." Not marketing, not a CV voice.
- **Do not give away the session.** The page carries the giveaways, a short seven-parts summary
  and contact links. It does not carry the full session notes.
- **Folder means a topic explained; tile means a thing given.** Business Analytics Skills is one
  tile at the root because it is a repo he hands over.
- **The ruling and vignette are fixed**; content scrolls over them.
- **Motion:** the heading changes by ink settling. Anything that must finish animates `transform`
  or `opacity`, never `stroke-dashoffset` (it stalls when the tab is not painting). Respect
  reduced motion.
- **Public means public.** This repo is public and is served as a website. No secret of any kind
  goes in it, and anything beyond the page's own subject stays out. His standing rules about what
  to keep out of public material are in his Ownr memory; read them first. His email is assembled
  in JavaScript on purpose, not written in the markup.
- **Tell him before changing a plan.** If a better approach appears, say so and get a yes first.

## Locking a page or folder behind a PIN

A node can carry `lock=dict(unlock="deck", hint="...")`. A locked tile then opens a pop-up asking
for a four-digit PIN instead of a page. Two nodes use it, with the same PIN: "The slides"
(`unlock="deck"`, which leaves for the deck) and "Business Analytics Skills" (`unlock="open"`,
which opens the page here and keeps it open for the visit). The check is a server function
elsewhere (a Vercel project, `api/unlock.js`) that is **not in this repo**. That server only
answers pages on an allowed origin (moheetsubudhi.com, the github.io address, and the staging
previews), so a new domain has to be added there or every PIN will fail. A
locked folder would need its own server-side check; the pop-up is reusable, the unlock is not.
Do not invent a client-side PIN: it would sit in the page source and protect nothing.

## Verify every change like this

He reviews by screenshot and catches anything you only checked once. After any change, check
**every page, at 1440x880 and at 375x812**, for: no horizontal overflow, no page scroll on a
poster, no overlapping tiles, every tile clickable, the heading centred and clear of the top bar,
back climbing exactly one level, and search reaching the new node. Say plainly what you measured.

Paste this into the browser console on the served page. It walks every node:

```js
const w = ms => new Promise(r => setTimeout(r, ms)); const bad = [];

    const t = [...document.querySelectorAll('#hub .obj')].filter(o => !o.hidden);

      const x = b[i], y = b[j];

    }
    off = !t.every(o => { const r = o.getBoundingClientRect();
```

## Traps this codebase has already hit

- The page is one big Python f-string. Embedded JS and CSS braces must be doubled (`{{ }}`), or
  you get `f-string: expecting a valid expression`.
- `display` on an element beats the `hidden` attribute. A global `[hidden]{display:none!important}`
  exists for this. Do not remove it.
- Hidden panes measure as zero, so lay out when a poster becomes visible, not at load.
- `layoutScatter` must only touch the tiles currently shown, not every tile in the page.
- `requestAnimationFrame` can be throttled in previews. Use CSS classes and timers.
- `history.pushState` throws on `file://`; `setUrl` falls back to the hash.
- A CSS animation only plays on a new element. Text that must re-animate is rewritten as fresh
  spans.
- iOS Safari ignores `background-attachment:fixed`; the ruling is a `position:fixed` pseudo-element.
- GitHub redirects a renamed repo but not the Pages site it publishes. The old
  `build-with-ai` repo is a one-page redirect for that reason. Do not rename this repo casually.
- After editing, grep for duplicate function definitions. A past edit injected a second copy of
  `layoutScatter` into the CSS block and a later fix edited the dead copy.
- Check what you are testing. Twice a stale copy of the page was open in the preview and a
  working change looked broken.
